# 多武器计算与服务器地图联动（0.4.0）

更新：2026-10-25。参考 [SquadCalc 网页](https://squadcalc.app/)及仓库 HEAD [`24828d6d3081c7ce52b10ef39ec86036ebf010b5`](https://github.com/sh4rkman/SquadCalc/tree/24828d6d3081c7ce52b10ef39ec86036ebf010b5)。本轮重新确认 HEAD，未沿用过期分支假设。

## 使用方式

左上角选择“工事 / 载具”、武器和弹药。参数、仰角显示单位和射程参考圈会即时变化；保持当前地图、炮位、目标和高度模式。关窗后保存武器及弹药 ID；旧设置缺少这些字段时仍使用标准迫击炮。

进入服务器列表后，点选行仅查看详情。点击“启用地图跟随”后仍停留列表，手动切换到射击页才同步地图。跟随期间每 60 秒刷新地图信息，后台不核验人数。停止跟随或手动修改射击地图后，不再为跟随发起网络请求。跟随关系不跨重启自动恢复。0.5.1 的按模式跟随和基地国旗见 [SERVER_FOLLOW_AND_FLAGS.md](SERVER_FOLLOW_AND_FLAGS.md)。

未知地图、缺失服务器或不支持的模组层保留当前底图并提示原因；不会将列表自动选中的第一行当成用户选择。同一底图刷新保留精确坐标；切到另一底图时重置旧坐标、缩放和高程。0.5.0 的独立“RAAS 猜点”模式另外加载内置旗点与路线，见 [RAAS.md](RAAS.md)；射击模式不绘制这些标记。

## 计算与限制

先扣除武器对应炮口高度，计算高/低弹道，再减去瞄具角度偏移得到游戏读数。飞行时间根据未扣瞄具偏移的真实发射角计算，使用同一炮口高差；避免把 Tech. Mortar 的 5° 修正误当作物理发射角。默认解不可用时采用另一有效解，弹丸寿命不足时不提供可用读数。

UB-32 沿用上游 `getVelocity(distance)` 近似，减速为 50 m/s²、阶段为 2 秒；它不是阻力或分段轨迹模拟，上游公式在阶段边界附近存在不连续。界面和文档均标明为近似，未经游戏验证。射程圈同样采用上游平地参考公式，不保证圈内所有目标都满足实际仰角、寿命或地形条件。

网页实测中，公开服务器选择从 Al Basrah 切到了 [Gorodok / Invasion v3](https://squadcalc.app/?map=Gorodok&layer=Invasionv3&server=41527458)，页面同时加载旗点和阵营数据。本地版复现底图与高程联动；地图层名称由 EOS 的 `MAPNAME_s` 提供，按已知基础地图名精确归一化，覆盖 `JensensRange`、`KohatToi`、`PacificProvingGrounds` 等别名。相关上游流程见 [squadServersBrowser.js](https://github.com/sh4rkman/SquadCalc/blob/24828d6d3081c7ce52b10ef39ec86036ebf010b5/src/js/squadServersBrowser.js)。

数学回代、旧迫击炮测试、WPF 页面与本地设置读写测试不能替代游戏内命中测试。当前没有重新验证实际进服，也没有在游戏里校准新增武器。

0.4.1 构建验证包含 711 项武器与地图联动断言、30 项服务器页面断言，以及原核心 2624 项、地图数据 211 项、绘制与输入 694 项、服务器模型 102 项断言，共 4372 项。桌面启动截图另行检查；测试不连接 EOS 或 Steam，设置读写仅使用测试临时目录。该版本已移除 Steam 加入功能及对应组件和测试。

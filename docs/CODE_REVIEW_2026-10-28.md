## 为什么高程会为负

`TerrainHeightMap.Sample` 使用：

```text
高度图编码值 = (255 + R - B) × heightScale
SDK 地表高程 = 高度图编码值 + heightOffset
高差 = 目标 SDK 地表高程 - 炮位 SDK 地表高程
```

`heightOffset` 来自上游地图的 `SDK_data.zOffset`。[上游三维标定说明](https://github.com/sh4rkman/SquadCalc/blob/24828d6d3081c7ce52b10ef39ec86036ebf010b5/src/js/squad3DSimulation.js#L1840)明确它用于恢复真实 Unreal 世界 Z；[上游二维采样](https://github.com/sh4rkman/SquadCalc/blob/24828d6d3081c7ce52b10ef39ec86036ebf010b5/src/js/squadHeightmaps.js#L47)计算高差时无需加这个共同偏移。两种基准下的绝对显示值不同，两点高差一致。

Mestia 的偏移为 `-153.9385 m`。例如编码高度为 `75.06244257 m` 和 `95.80338065 m` 的两个点，恢复 SDK 基准后为 `-78.87605743 m` 和 `-58.13511935 m`，高差在两种基准下都约为 `+20.74093808 m`。负号表示低于地图坐标零点，不表示目标一定低于炮位，更不代表海平面以下。

不能通过取绝对值、截断成 0 或仅修正一侧来让显示变正，那会破坏高低关系或高差。当前保留原始有效值，并解释其含义。

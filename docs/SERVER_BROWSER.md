# 服务器列表 0.4.1 预览版

更新：2026-10-25。功能与迫击炮合并在同一个 Windows x64 程序中。

## 使用

点击顶部“服务器列表”联网查询。支持搜索、分类、收藏、隐藏空服、折叠相同连接入口。仅切换页面会保留炮位与目标；明确选择另一地图时重置坐标。服务器页停留时每 60 秒刷新，没有跟随服务器时离开会暂停查询。手动列表刷新至少间隔 10 秒。

点击服务器行或按 Enter 可同步底图和地形高程，并返回射击页；会每 60 秒继续查询所跟随服务器的地图，后台不自动核验人数。点击“停止跟随服务器地图”或手动换图即停止后台跟随。自动选中首行、搜索、排序、收藏和刷新不会选取其他服务器；缺失会话、未知地图或模组地图不自动猜测底图。同一底图再次刷新不重置精确炮位。匹配范围及武器配置见 [说明](WEAPONS_AND_SERVER_MAPS.md)。

数据直接查询 Epic Online Services，不需要填写 Steam 密码或运行自己的后台。查询凭据仅放在进程内存中。默认刷新后核验当前筛选结果中人数最多的前 10 台，每批最多 5 台；其余服务器可以选择后点击“核验所选人数”。不会自动扫描和核验全列表。

0.4.1 按用户要求移除“加入（实验性）”及 Steam 组件。服务器页提供查询、核验、收藏和地图同步，查询不要求 Steam 运行。

列表刷新、核验与收藏操作保留用户选择的列排序。收藏文件无法读取或根节点不符合格式时暂停写入，避免覆盖原文件；修复 `data/server-favorites.xml` 后重启可恢复收藏。

## 数据含义

| 界面 | 来源与含义 |
| --- | --- |
| 上报人数 | `PLAYERCOUNT_l`；服务器发布的人数 |
| EOS 登记 | 会话的 `totalPlayers`，与上报口径分开保留 |
| 可见成员 | 根据目标 Session ID 查询公开在线状态，按 `USERID_s` 去重计数 |
| 排队 / 预留 | `PUBLICQUEUE_l` / `RESERVEDQUEUE_l` |
| 公开容量 | `settings.maxPublicPlayers`，不把它当作含预留位置的总容量 |
| 更新时间 | 本程序最近一次成功取得列表的本地时间 |
| 核验时间 | 取得此服务器可见成员的时间 |

可见成员可能包括尚在加载、短暂滞留等状态，也可能缺失。它不是游戏内完整名单，不能证明真人活跃。普通使用不解析玩家姓名，不持久化玩家标识或查询 token。

请求失败、响应缺字段、无可见成员或结果达到查询上限时，不把人数推断为 0。列表请求最多 1000 条；达到上限或发现响应不完整时标记“部分结果”，不承诺全球列表完整。

## 异常与合并规则

- 同一 Session ID 的重复查询结果合并。
- 选择同入口记录时优先使用有效更新时间；缺失、无效或晚于本地查询时刻的时间视为未知，不伪装成最新记录。
- 相同有效公网地址和游戏端口的不同会话可折叠，保留“同入口×N”说明，取消勾选可展开。
- `0.0.0.0`、内网、回环及链路本地等地址不能用于合并；缺地址的记录按会话独立保留。同 IP 不同端口互不合并。
- 同名不作为合并依据；折叠入口不证明哪条是原服，也不证明服主身份。
- 上报人数比可见成员至少多 `max(10, 上报人数×20%向上取整)` 时记录一次显著差异。
- 至少两次间隔 20–180 秒的差异样本才提示“持续人数差异”。恢复、样本不完整或没有可见成员会清除连续判定。
- 核验显示超过 180 秒过期，即使网络持续失败也会解除旧隐藏判定；列表人数发生变化时清除旧的连续差异样本。缺少上报人数时明确显示无法比较。
- “隐藏持续人数差异”默认关闭，由用户选择。阈值是可解释的初始规则，未经有标签的真假服样本集校准，不提供检出率承诺。

本版没有服主 RCON 接入、可信服主身份登记或玩家行为识别，因此不能完全还原所有服务器的真人情况。

## 实现与来源

- `src/ServerModels.cs`：字段解析、地址规范化、去重、筛选和核验状态；保留不同人数口径。
- `src/EosClient.cs`：固定 HTTPS EOS 目标、device ID 认证、内存 token、20 秒请求超时、取消与限流提示。协议参考 GameDig 的 `squad.js` / `epic.js`，MIT 许可随包保留。
- `src/ServerBrowserView.cs`：WPF 页面、异步刷新、筛选和收藏，不阻塞地图操作。
- `src/ServerDiagnostics.cs`：显式运行的联网诊断与离线界面验证入口，普通用户启动不执行。

代码沿用现有 .NET Framework 4.8 / C# 5 构建方式，服务器查询仅使用 Framework 自带组件。构建会清理旧生成目录中已知的 Steam 加入文件，便携包验证禁止包含这些组件。

协议与示例资料详见 [前期调研](SERVER_BROWSER_RESEARCH.md)。调研文档中的“未实测”描述是开发前记录，以本页的验证范围为准。
